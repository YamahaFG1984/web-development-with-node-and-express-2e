第 6 章

Context：请求与响应

处理函数拿到的那个 c，是你和整个 HTTP 世界之间的唯一接口。 这一章把它拆开来看：URL 由哪些部分组成、有哪些方法和头、怎么读请求、怎么造响应。

本章目标

  • 能说清 URL 的六个组成部分，知道哪些会传到服务器
  • 掌握 c.req 上常用的读取方法
  • 掌握 c.text/json/html/redirect 等造响应的方法
  • 知道什么时候该绕过 Hono，直接用标准的 Request/Response

URL 的组成

ⓘ 片段为什么看不到

#photos 是浏览器的私事 —— 原本用来滚动到锚点，后来被一些单页应用拿去做前端路由。 浏览器发请求时会把 # 及之后的部分截掉。所以服务端逻辑永远不能依赖它。

HTTP 方法

同一个路径 /vacations，配上不同的方法，含义完全不同。这是 REST 风格的基础：

方法语义有请求体吗可重复执行吗
GET取数据没有可以（不改变任何东西）
POST新建有不可以（重复提交会创建两条）
PUT整体替换有可以（结果一样）
PATCH局部修改有通常可以
DELETE删除通常没有可以
OPTIONS问「我能做什么」没有可以（CORS 预检用它，第 17 章讲）

浏览器地址栏和普通链接只会发 GET；HTML 表单只支持 GET 和 POST。 其余方法要靠 JavaScript 的 fetch() 发出。

app.get('/vacations', listVacations)          // 列表
app.post('/vacations', createVacation)         // 新建
app.get('/vacations/:sku', getVacation)        // 单个
app.put('/vacations/:sku', replaceVacation)    // 整体替换
app.delete('/vacations/:sku', deleteVacation)  // 删除

app.all('/webhook', handleWebhook)             // 任意方法
app.on(['GET', 'HEAD'], '/ping', pong)         // 指定若干方法

请求头与响应头

除了 URL，浏览器每次还会附带一堆请求头。写个路由把它们打印出来看看： 

app.get('/headers', (c) => {
  const lines: string[] = []
  // c.req.raw.headers 是标准的 Headers 对象，可以直接遍历
  c.req.raw.headers.forEach((value, key) => {
    lines.push(`${key}: ${value}`)
  })
  return c.text(lines.join('\n'))
})

你会看到类似这些：

请求头它告诉服务器什么
accept我能接受什么格式（HTML？JSON？）
accept-language我偏好什么语言（可用于自动切换中英文）
user-agent我是什么浏览器、什么系统
cookie你上次给我存的东西（第 9 章）
content-type我的请求体是什么格式（第 8 章）
authorization我的身份凭证（第 20 章）

反过来，服务器用响应头告诉浏览器怎么处理返回的内容：

响应头作用
Content-Type这是什么格式。最重要的一个
Cache-Control能缓存多久（第 19 章）
Set-Cookie请存下这个值（第 9 章）
Location去这个地址（配合 3xx 状态码）
Content-Security-Policy只许加载这些来源的脚本（第 20 章）
★ Content-Type 决定一切

浏览器完全按 Content-Type 来解释响应内容，和 URL 后缀无关。 你可以在 /image.jpg 返回 HTML，也可以在 /page.html 返回 PNG。 路径只是个名字，格式由响应头说了算。这也是为什么 c.json() 和 c.html() 这类快捷方法有价值 —— 它们不让你忘记设这个头。

媒体类型

Content-Type 的值叫互联网媒体类型（旧称 MIME 类型），格式是 类型/子类型; 参数： 

text/html; charset=utf-8          HTML 页面
text/plain; charset=utf-8         纯文本
application/json                  JSON
image/png                         PNG 图片
application/x-www-form-urlencoded 普通表单提交
multipart/form-data               带文件的表单

读请求：c.req

Hono 把请求信息都挂在 c.req 上（类型叫 HonoRequest）：

写法拿到什么
c.req.method方法字符串，如 'GET'
c.req.url完整 URL 字符串
c.req.path路径，如 '/vacations/hr199'
c.req.routePath匹配到的路由模式，如 '/vacations/:sku'。调试路由时很有用
c.req.param('sku')单个路径参数
c.req.param()所有路径参数组成的对象
c.req.query('q')单个查询串参数
c.req.query()所有查询串参数组成的对象
c.req.queries('tag')同名参数的数组，如 ?tag=a&tag=b
c.req.header('accept')单个请求头（不区分大小写）
await c.req.json()把请求体解析成 JSON
await c.req.text()请求体的纯文本
await c.req.parseBody()解析表单（含文件），第 8 章详讲
await c.req.formData()标准 FormData 对象
await c.req.arrayBuffer()原始字节
c.req.valid('json')校验器验证过的数据，第 8 章详讲
c.req.raw原始的标准 Request 对象，Hono 没包装的东西从这里拿
app.get('/vacations/:sku', (c) => {
  const sku = c.req.param('sku')                // 路径参数
  const currency = c.req.query('currency') ?? 'CNY'  // 查询串，带默认值
  const lang = c.req.header('accept-language')  // 请求头
  return c.json({ sku, currency, lang })
})
⚠ 请求体只能读一次

请求体是一个流。await c.req.text() 之后再 await c.req.json() 会失败或拿到空值。需要多次使用同一份数据，先读出来存到变量里。 （Hono 内部对 c.req.json() 等方法做了缓存，但混用不同方法仍然容易出问题，养成读一次的习惯。）

造响应

写法做什么
c.text('hi')纯文本，自动设 text/plain; charset=UTF-8
c.json({ a: 1 })JSON，自动设 application/json
c.html(<Page />)HTML，接受 JSX 或字符串
c.redirect('/about')重定向，默认 302
c.redirect('/about', 303)指定重定向状态码
c.notFound()触发 app.notFound() 的处理逻辑
c.body(data, 200, headers)任意内容 + 状态码 + 响应头
c.newResponse(...)完全自定义构造
c.header('X-Foo', 'bar')设置一个响应头
c.status(201)设置状态码
c.res当前的 Response 对象（中间件里改响应用）

状态码可以直接作为第二个参数传：

app.get('/teapot', (c) => c.text('我是茶壶', 418))

app.post('/vacations', (c) => c.json({ ok: true }, 201))   // 201 Created

app.get('/old-page', (c) => c.redirect('/new-page', 301))  // 永久重定向

常用状态码

码名字什么时候用
200OK成功（默认值）
201CreatedPOST 成功创建了资源
204No Content成功但没有返回内容（如 DELETE）
301Moved Permanently永久搬家。浏览器会缓存，慎用
302Found临时跳转
303See Other表单提交后跳转的正确选择（第 8 章解释为什么）
304Not Modified内容没变，用你的缓存（第 19 章）
400Bad Request客户端参数有问题
401Unauthorized没登录（其实是「未认证」，名字取错了）
403Forbidden登录了但没权限
404Not Found资源不存在
409Conflict和现有数据冲突（如邮箱已注册）
422Unprocessable Entity格式对但内容不合法（校验失败）
429Too Many Requests限流
500Internal Server Error服务器自己出错了

需要时可以绕过 Hono

Hono 的封装是可选的。任何时候你都能拿到原始对象，也能直接返回标准 Response： 

app.get('/raw', (c) => {
  const request: Request = c.req.raw   // 标准 Request

  // 直接返回标准 Response，Hono 完全接受
  return new Response('自己造的响应', {
    status: 200,
    headers: { 'Content-Type': 'text/plain; charset=utf-8' },
  })
})
💡 这就是「不锁定」的含义

很多框架的封装是不透明的：一旦框架没提供某个能力，你就卡住了。 Hono 的封装是透明的：c.req.raw 永远在那儿，你随时能掉回标准层。 学 Hono 的时间不会浪费，因为你学的大部分是 Web 标准本身。

三种常见模式速查

① 渲染页面

// 最简单
app.get('/about', (c) => c.html(<About />))

// 带状态码
app.get('/gone', (c) => c.html(<Gone />, 410))

// 从查询串取数据传给视图
app.get('/greeting', (c) => {
  const name = c.req.query('name') ?? '朋友'
  return c.html(<Greeting name={name} />)
})

// 返回纯文本（调试时方便）
app.get('/debug', (c) => c.text(JSON.stringify(c.req.query(), null, 2)))

② 处理表单

app.post('/contact', async (c) => {
  const body = await c.req.parseBody()
  const name = String(body.name ?? '')
  const email = String(body.email ?? '')

  if (!email.includes('@')) {
    return c.html(<ContactError />, 400)
  }

  console.log(`收到联系请求：${name} <${email}>`)
  // 303 而不是 302：确保浏览器用 GET 访问下一个地址
  return c.redirect('/contact/thank-you', 303)
})

③ 提供 API

const tours = [
  { id: 0, name: '胡德河一日游', price: 99.95 },
  { id: 1, name: '俄勒冈海岸', price: 149.95 },
]

app.get('/api/tours', (c) => c.json(tours))

app.get('/api/tours/:id', (c) => {
  const id = Number(c.req.param('id'))
  const tour = tours.find((t) => t.id === id)
  if (!tour) return c.json({ error: '没有这个行程' }, 404)
  return c.json(tour)
})

app.put('/api/tours/:id', async (c) => {
  const id = Number(c.req.param('id'))
  const tour = tours.find((t) => t.id === id)
  if (!tour) return c.json({ error: '没有这个行程' }, 404)

  const patch = await c.req.json<{ name?: string; price?: number }>()
  if (patch.name !== undefined) tour.name = patch.name
  if (patch.price !== undefined) tour.price = patch.price
  return c.json(tour)
})

app.delete('/api/tours/:id', (c) => {
  const id = Number(c.req.param('id'))
  const idx = tours.findIndex((t) => t.id === id)
  if (idx < 0) return c.json({ error: '没有这个行程' }, 404)
  tours.splice(idx, 1)
  return c.body(null, 204)   // 204 表示成功但无内容
})
⚠ 上面的 tours 数组是玩具

它存在服务器进程的内存里。重启就没了，而且如果你跑了两个实例，两边的数据会不一致。 第 13 章会换成真正的数据库。现在这样写只是为了聚焦在请求/响应上。

小结

  • URL 有六个部分，# 之后的片段永远不会到服务器。
  • Content-Type 决定浏览器怎么解释响应，和路径后缀无关。
  • 读请求全靠 c.req.*，造响应全靠 c.text/json/html/redirect/body。
  • 请求体是流，只能读一次。
  • c.req.raw 让你随时回到标准 Request；直接 return new Response(...) 也完全合法。

动手练习

  1. 写一个 /inspect 路由，把方法、路径、查询串、所有请求头都以 JSON 返回。用 curl 和浏览器各访问一次，对比差异。
  2. 写一个 /lang 路由：读 accept-language 头，如果包含 zh 返回中文问候，否则返回英文。
  3. 用 curl -X DELETE http://localhost:3000/api/tours/0 -i 试试上面的删除接口，观察 204 响应确实没有响应体。
  4. 把 /api/tours 改成：如果请求头 accept 里包含 text/html 就返回一个 HTML 表格，否则返回 JSON。
