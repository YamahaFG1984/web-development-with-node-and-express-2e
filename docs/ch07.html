第 7 章

模板与视图

模板解决一个很老的问题：怎么在不把 HTML 拼成字符串的前提下，往页面里塞动态数据。 Hono 的答案是 JSX —— 用写 HTML 的方式写，但它是真的 JavaScript。

本章目标

  • 理解「上下文 + 模板 = HTML」这个基本模型
  • 用 JSX 写组件、布局、条件渲染和列表渲染
  • 用 jsxRenderer 中间件把布局统一起来
  • 理解自动转义为什么保护你，以及什么时候需要 raw()
  • 知道 html 标签函数这个不用 JSX 的备选方案
  • 在模板层就把可访问性做对 —— 这是成本最低的时机

为什么不能直接拼字符串

看看不用模板会变成什么样：

// 千万别这样写
let html = '<div class="error"><h3>出错了</h3>'
html += '<p>发生了 <b><a href="/error/' + errorNumber + '">严重问题</a></b>。'
html += '请<a href="/retry">重试</a>，或<a href="/contact">联系客服</a>。</p></div>'

问题一眼可见：

  • 引号嵌套地狱，少一个引号就全乱。
  • 编辑器不知道这是 HTML，没有高亮、没有补全、没有格式化。
  • 标签没闭合也不会报错，运行时才发现页面塌了。
  • 最危险的：如果 errorNumber 来自用户输入，用户可以塞进去 <script> —— 这就是 XSS 攻击。

模板的核心思路：用目标语言（HTML）来写，只在需要的地方开个口子插数据。

Hono 的几种选择

方案写法什么时候用
JSX（推荐） hono/jsx，内置 绝大多数情况。有类型检查，组件可组合，写过 React 就会
html 标签函数 hono/html，内置 不想配 JSX、或只需要拼一小段 HTML（比如邮件）
传统模板引擎 ejs / handlebars 等 迁移老项目，或非程序员要改模板
ⓘ 关于 Handlebars

原书用的是 Handlebars（{{name}} 那种语法）。它现在依然能用， 但在 TypeScript 项目里有个硬伤：模板里的变量名写错了，编译器不会告诉你， 要等页面渲染出来才发现少了一块。JSX 是真正的 JavaScript，写错变量名当场红波浪线。 这是本教程选 JSX 的主要原因。

JSX 基础

JSX 是 JavaScript 的语法扩展，允许你在代码里直接写标签。编译后它就是普通的函数调用：

你写的
<h1 class="title">你好</h1>
编译成
jsx('h1', { class: 'title' }, '你好')

插值

const name = '云雀'
const items = ['帆船', '啤酒', '风筝冲浪']

const view = (
  <div>
    {/* 这是 JSX 注释，不会出现在 HTML 里 */}
    <h1>{name}旅行</h1>

    {/* 表达式随便写 */}
    <p>共 {items.length} 个项目，人均 ¥{(299 / 2).toFixed(2)}</p>

    {/* 属性插值 */}
    <a href={`/vacations/${name}`} title={name}>查看</a>
  </div>
)

条件渲染

// 方式一：&& —— 条件成立才渲染
{inSeason && <span class="badge">当季</span>}

// 方式二：三元 —— 二选一
{inSeason
  ? <button>立即预订</button>
  : <a href={`/notify?sku=${sku}`}>到季节时通知我</a>}

// 方式三：提前算好，让 JSX 保持干净
const badge = inSeason ? '当季' : '暂停销售'
return <span>{badge}</span>
⚠ 用 && 时小心数字 0

{count && <p>有 {count} 条</p>} 在 count 为 0 时会渲染出一个「0」。 因为 0 && x 的结果是 0，而 0 是会被渲染的。 写成 {count > 0 && ...} 就好了。

列表渲染

<ul>
  {vacations.map((v) => (
    <li>
      <h3>{v.name}</h3>
      <p>{v.description}</p>
      <span class="price">¥{v.price.toFixed(2)}</span>
    </li>
  ))}
</ul>

{/* 空列表也要处理 */}
{vacations.length === 0 && <p>暂时没有可预订的行程。</p>}

Fragment：不想多包一层 div

// <>...</> 是 Fragment 的简写，渲染时不产生任何标签
const Price = ({ v }) => (
  <>
    <dt>价格</dt>
    <dd>¥{v.price}</dd>
  </>
)

组件与组合

一个组件就是一个返回 JSX 的函数。没有类，没有生命周期，服务端渲染就这么简单。 

import type { FC } from 'hono/jsx'

type Vacation = {
  sku: string
  name: string
  description: string
  price: number
  inSeason: boolean
}

// 一张度假卡片
export const VacationCard: FC<{ vacation: Vacation }> = ({ vacation: v }) => (
  <article class="vacation">
    <h3>{v.name}</h3>
    <p>{v.description}</p>
    {v.inSeason ? (
      <>
        <span class="price">¥{v.price.toFixed(2)}</span>
        <a class="btn" href={`/cart/add?sku=${v.sku}`}>立即预订</a>
      </>
    ) : (
      <p class="out-of-season">
        当前不在季节内。
        <a href={`/notify-me?sku=${v.sku}`}>到季节时通知我</a>
      </p>
    )}
  </article>
)

// 一个列表，复用上面的卡片
export const VacationList: FC<{ vacations: Vacation[] }> = ({ vacations }) => (
  <section>
    <h2>精选行程</h2>
    {vacations.length === 0
      ? <p>暂时没有可预订的行程。</p>
      : vacations.map((v) => <VacationCard vacation={v} />)}
  </section>
)
★ 类型检查在这里救你

如果你把 <VacationCard vaction={v} />（拼错了）或者忘了传 vacation， TypeScript 立刻报错。用字符串模板引擎的话，这两种错误都要等到页面渲染出来看到空白才发现。

布局

每个页面都要重复的 HTML 骨架，抽成布局组件（第 3 章已经写过一个）：

import type { FC, PropsWithChildren } from 'hono/jsx'

type LayoutProps = PropsWithChildren<{
  title?: string
  /** 额外塞进 <head> 的内容，比如 meta 标签 */
  head?: unknown
  /** 塞在 </body> 前的脚本 */
  scripts?: unknown
}>

export const Layout: FC<LayoutProps> = ({ title, head, scripts, children }) => (
  <html lang="zh-CN">
    <head>
      <meta charset="utf-8" />
      <meta name="viewport" content="width=device-width,initial-scale=1" />
      <title>{title ? `${title} · 云雀旅行` : '云雀旅行'}</title>
      <link rel="stylesheet" href="/css/main.css" />
      {head}
    </head>
    <body>
      <header>
        <a href="/"><img src="/img/logo.png" alt="云雀旅行" width="120" /></a>
        <nav>
          <a href="/vacations">行程</a>
          <a href="/about">关于</a>
        </nav>
      </header>
      <main>{children}</main>
      <footer>&copy; 2026 云雀旅行</footer>
      {scripts}
    </body>
  </html>
)

head 和 scripts 这两个 prop 解决了一个经典难题： 某个页面想往 <head> 里加东西，或者在页面底部插一段脚本。 原书里这叫「section」，在 JSX 里它就是普通的 prop： 

export const SecretPage: FC = () => (
  <Layout
    title="内部页面"
    head={<meta name="robots" content="noindex" />}
    scripts={<script src="/js/analytics.js" defer></script>}
  >
    <h1>这个页面不希望被搜索引擎收录</h1>
  </Layout>
)

jsxRenderer：让布局自动生效

每个页面组件都手动包一层 <Layout> 有点啰嗦。 jsxRenderer 中间件可以把布局设成默认的，之后用 c.render() 只写页面内容： 

import { jsxRenderer } from 'hono/jsx-renderer'

app.use(
  '*',
  jsxRenderer(({ children, title }) => (
    <html lang="zh-CN">
      <head>
        <meta charset="utf-8" />
        <title>{title ?? '云雀旅行'}</title>
        <link rel="stylesheet" href="/css/main.css" />
      </head>
      <body>
        <header><a href="/">云雀旅行</a></header>
        <main>{children}</main>
      </body>
    </html>
  ))
)

// 之后路由里只写内容部分
app.get('/about', (c) =>
  c.render(<h1>关于云雀旅行</h1>, { title: '关于我们' })
)
💡 两种方式怎么选

显式包 <Layout>：更直白，看组件就知道用了哪个布局，适合布局种类多的站点。
jsxRenderer：路由代码更干净，适合全站布局统一的情况。而且它可以按路径分组 —— 给 /admin/* 挂一个后台布局，给其他路径挂前台布局。

自动转义与 raw

这是模板系统最重要的安全特性。看这段代码：

const userInput = '<script>alert("我偷你 cookie")</script>'

return <p>评论：{userInput}</p>

渲染出来是：

<p>评论：&lt;script&gt;alert(&quot;我偷你 cookie&quot;)&lt;/script&gt;</p>

浏览器会把它当成文字显示，而不是执行。< 被换成了 &lt;。 这叫 HTML 转义，JSX 默认对所有插值都做这件事。

确实需要输出 HTML 时

有些场景你真的想输出 HTML —— 比如富文本编辑器存下来的内容，或者 Markdown 渲染的结果： 

import { raw } from 'hono/html'

// 方式一：raw()
<div>{raw(trustedHtml)}</div>

// 方式二：dangerouslySetInnerHTML（名字就在警告你）
<div dangerouslySetInnerHTML={{ __html: trustedHtml }} />
⚠ 只对「已经清洗过」的内容用

raw() 关掉的正是保护你的那道门。用之前问自己：这段 HTML 是谁产生的？ 如果它有任何可能来自用户，必须先用 DOMPurify 这类库清洗。「我们的用户不会干坏事」不是一个安全假设。

不用 JSX：html 标签函数

如果你不想配 JSX，或者只是要拼一小段 HTML（比如邮件正文，第 11 章会用到）， hono/html 提供了一个模板字符串方案，同样自动转义： 

import { html } from 'hono/html'

const Card = (v: { name: string; price: number }) => html`
  <article class="vacation">
    <h3>${v.name}</h3>
    <span>¥${v.price.toFixed(2)}</span>
  </article>
`

app.get('/card', (c) => c.html(html`
  <!doctype html>
  <html>
    <body>${Card({ name: '胡德河一日游', price: 99.95 })}</body>
  </html>
`))
ⓘ 注意这个 html 前缀不能省

普通模板字符串 `<p>${x}</p>` 不会转义。 只有加了 html 标签函数前缀，${} 里的内容才会被转义。 这一个字符的差别，就是有没有 XSS 漏洞的差别。

可访问性

可访问性（accessibility，常缩写为 a11y）是指让有视觉、听觉、运动或认知障碍的人也能使用你的网站。 它在很多国家和地区已经是法律要求，不再只是加分项。

好消息是：绝大部分可访问性来自「把 HTML 写对」， 而模板层正是写 HTML 的地方 —— 所以这里是成本最低的时机。在这一层做对，之后就一直是对的。

六条覆盖八成问题的规则

{/* ① 图片必须有 alt。装饰性图片用空 alt，让屏幕阅读器跳过 */}
<img src="/img/hood-river.jpg" alt="帆船在胡德河上航行" />
<img src="/img/divider.svg" alt="" />              {/* 纯装饰 */}

{/* ② 表单控件必须有关联的 label */}
<label for="email">邮箱</label>
<input id="email" name="email" type="email" />

{/* placeholder 不能代替 label —— 输入后它就消失了，而且对比度通常不够 */}

{/* ③ 用语义标签划分页面区域 */}
<header>…</header>
<nav aria-label="主导航">…</nav>
<main>…</main>          {/* 一个页面只能有一个 main */}
<footer>…</footer>

{/* ④ 标题层级不能跳，它是屏幕阅读器的目录 */}
<h1>云雀旅行</h1>
  <h2>精选行程</h2>
    <h3>胡德河一日游</h3>
{/* 不要为了字号小就用 h4 —— 字号用 CSS 控制 */}

{/* ⑤ 链接文字要能独立看懂 */}
<a href="/vacations/hr199">查看胡德河一日游详情</a>
{/* ❌ 屏幕阅读器可以只念出页面所有链接，一堆「点击这里」毫无意义 */}

{/* ⑥ 语言要声明，屏幕阅读器据此选择发音 */}
<html lang="zh-CN">
<p>这个词在英文里叫 <span lang="en">serendipity</span>。</p>

表单错误要被「说」出来

第 8 章会讲表单校验。校验失败时，如果只是把错误文字渲染在输入框下面， 屏幕阅读器用户完全不知道发生了什么 —— 页面变了但没人告诉他。 

export const EmailField: FC<{ value?: string; error?: string }> = ({ value, error }) => (
  <div class="field">
    <label for="email">邮箱</label>
    <input
      id="email"
      name="email"
      type="email"
      value={value}
      required
      {/* 告诉辅助技术：这个控件当前处于错误状态 */}
      aria-invalid={error ? 'true' : undefined}
      {/* 把错误信息和输入框关联起来，聚焦时会被一起念出来 */}
      aria-describedby={error ? 'email-error' : undefined}
    />
    {error && (
      <p id="email-error" class="error" role="alert">
        {error}
      </p>
    )}
  </div>
)
★ role="alert" 和 aria-live

动态出现的内容（校验错误、「保存成功」提示、搜索结果数量）需要主动通知辅助技术：

  • role="alert" —— 立即打断并播报。用于错误、警告。
  • aria-live="polite" —— 等用户空闲时播报。用于状态更新、结果计数。

第 9 章的 Flash 消息、第 14 章的搜索结果都用到了它。 注意：这个容器必须在页面加载时就存在（哪怕是空的）， 后来才插入的 aria-live 元素可能不会被播报。

键盘可用性

要求怎么验证
所有交互元素都能用 Tab 到达把鼠标拿开，只用键盘走一遍主流程。这是最有效的一次性检查
焦点位置始终可见不要写 outline: none。要改样式就用 :focus-visible 提供替代
Tab 顺序符合视觉顺序不要用 tabindex 正数去调顺序，改 DOM 顺序
能跳过重复的导航页面开头放一个「跳到主内容」链接
弹窗打开时焦点进入、关闭时归还用原生 <dialog> 能免费拿到大部分行为
{/* 跳过导航链接：平时隐藏，被 Tab 聚焦时出现 */}
<a href="#main" class="skip-link">跳到主内容</a>
<nav>…几十个链接…</nav>
<main id="main" tabindex="-1">…</main>

.skip-link {
  position: absolute;
  left: -9999px;          /* 视觉上移出屏幕，但仍在无障碍树里 */
}
.skip-link:focus {
  left: 8px; top: 8px;
  background: #fff; padding: 8px 12px; z-index: 100;
}

/* ❌ 千万别这样 */
*:focus { outline: none; }

/* ✅ 要改就提供更好的替代 */
:focus-visible {
  outline: 3px solid #0b5fff;
  outline-offset: 2px;
}
⚠ outline: none 是可访问性头号杀手

很多 CSS reset 里都有这一行，因为设计师觉得那个蓝框不好看。
但对只用键盘的人来说，失去焦点指示等于失去光标 —— 他完全不知道自己现在选中的是哪个元素。
用 :focus-visible：鼠标点击时不显示轮廓，键盘导航时显示。两全其美。

颜色与对比度

规则说明
正文对比度 ≥ 4.5:1WCAG AA 级要求。大字号（18pt+）可以放宽到 3:1
不要只用颜色传达信息「红色表示错误」对色盲用户无效。要配上图标或文字
链接要能和正文区分只靠颜色不够，加下划线或其他视觉标记
支持深色模式和放大用相对单位（rem），别写死 px 高度导致文字放大后被裁切

怎么检查

方法能发现成本
只用键盘走一遍焦点丢失、无法到达的控件、顺序错乱五分钟，收益最高
浏览器 DevTools 的 Lighthouse / 无障碍面板缺 alt、对比度不足、标题层级问题一次点击
axe-core 接进 Playwright自动化，能进 CI（第 5 章）半小时接入
真的用一次屏幕阅读器前面几种都发现不了的体验问题需要学一点，但值得
import { test, expect } from '@playwright/test'
import AxeBuilder from '@axe-core/playwright'

test('首页没有可访问性违规', async ({ page }) => {
  await page.goto('/')
  const results = await new AxeBuilder({ page })
    .withTags(['wcag2a', 'wcag2aa'])
    .analyze()

  expect(results.violations).toEqual([])
})
💡 自动化只能查出约三成问题

工具能发现「这个图片没有 alt」，但发现不了「alt 写的是 image1.jpg」。 能发现「对比度不足」，但发现不了「Tab 顺序让人摸不着头脑」。
把 axe 接进 CI 挡住回归，但真正的检查还是那五分钟的键盘走查。

模板的实践建议

  • 别把数据库对象直接扔给视图。先映射一遍，只传视图需要的字段。这样既不会不小心泄露 passwordHash 这类字段，也方便做格式化（价格加货币符号、日期本地化）。
  • 格式化在传给视图之前做。视图负责「长什么样」，不负责「算什么」。
  • 组件粒度别太细。把 <h3> 单独封装成组件没有收益，反而增加跳转成本。 按「能独立复用的东西」来切分。
  • 可访问性写在模板里。alt、label、语义标签（<nav>、 <main>、<article>）在这一层写好，之后就一直是对的。
// ✅ 先做一次映射（有些人管这个叫 view model）
app.get('/vacations', async (c) => {
  const rows = await db.getVacations({ available: true })

  const vacations = rows.map((v) => ({
    sku: v.sku,
    name: v.name,
    description: v.description,
    price: `¥${v.price.toFixed(2)}`,   // 格式化在这里做
    inSeason: v.inSeason,
    // 注意：internalNotes、cost 这些字段没有传给视图
  }))

  return c.html(<VacationsPage vacations={vacations} />)
})

小结

  • 模板 = 固定的形状 + 可插入的数据；不要用字符串拼 HTML。
  • JSX 组件就是返回 JSX 的函数，用 props 传数据，用 && 和三元做条件，用 map 做列表。
  • 布局用组件的 children 实现；需要往 <head> 插内容就多加一个 prop。
  • jsxRenderer 可以把布局变成中间件，路由里只写内容。
  • JSX 和 html 标签函数都会自动转义。raw() 关掉转义，只对可信内容使用。
  • 传给视图前先映射数据，别把数据库行对象直接透出去。
  • 可访问性八成来自「把 HTML 写对」：原生标签、alt、label、语义区域、标题层级。
  • 动态内容用 role="alert" / aria-live 播报；永远不要 outline: none。
  • 最有效的检查是把鼠标拿开，只用键盘走一遍。
