第 16 章

单页应用

前面十五章，页面都是服务器拼好 HTML 发过来的。这一章换个架构： 浏览器加载一次 JavaScript，之后自己渲染页面，Hono 退居幕后只提供 JSON。

本章目标

  • 理解 Web 应用架构的演变，知道 SPA 解决了什么、代价是什么
  • 用 Vite 建立一个 React 前端，和 Hono 后端协作
  • 用 RPC 客户端调用 API，享受端到端类型安全
  • 了解开发和生产两种部署形态
  • 知道 hono/jsx/dom 和 HonoX 这两个更轻的选择

简史

★ SPA 真正的价值

不是「页面不刷新」这个表象，而是把「界面应该长什么样」变成状态的纯函数。 你不再手动写「找到这个元素、改它的文字、隐藏那个按钮」，而是描述「当状态是 X 时界面就是 Y」， 剩下的交给框架。
这个收益在交互复杂时非常大，在展示型页面上则几乎不存在 —— 那种场景 SSR 更合适。

💡 开发时用代理，就不用配 CORS

前端跑在 5173 端口，后端在 3000。加上代理之后，浏览器看到的所有请求都来自 localhost:5173，同源，没有 CORS 问题。
生产环境两者部署在同一个域名下，同样不需要 CORS。只有前后端真的跨域时才配 CORS。

React 快速入门

如果你没写过 React，三个概念就够开始了。

① 组件

function VacationCard({ vacation }: { vacation: Vacation }) {
  return (
    <article className="vacation">
      <h3>{vacation.name}</h3>
      <p>{vacation.description}</p>
      <span>¥{vacation.price.toFixed(2)}</span>
    </article>
  )
}

和第 7 章的 Hono JSX 几乎一样。唯一区别：React 用 className，Hono JSX 用 class。

② 状态

import { useState } from 'react'

function Counter() {
  const [count, setCount] = useState(0)

  return (
    <button onClick={() => setCount(count + 1)}>
      点了 {count} 次
    </button>
  )
}

useState 返回「当前值」和「修改它的函数」。 调用修改函数时，React 会重新执行这个组件函数，用新的值渲染出新的界面。 这就是「状态 → 界面」的声明式模型。

③ 副作用

import { useEffect, useState } from 'react'

function VacationList() {
  const [vacations, setVacations] = useState<Vacation[]>([])
  const [loading, setLoading] = useState(true)
  const [error, setError] = useState<string | null>(null)

  useEffect(() => {
    let cancelled = false

    fetch('/api/v1/vacations')
      .then((res) => {
        if (!res.ok) throw new Error(`请求失败：${res.status}`)
        return res.json()
      })
      .then((body) => { if (!cancelled) setVacations(body.data) })
      .catch((err) => { if (!cancelled) setError(err.message) })
      .finally(() => { if (!cancelled) setLoading(false) })

    // 组件卸载时取消，避免对已卸载组件调用 setState
    return () => { cancelled = true }
  }, [])   // 空数组 = 只在组件首次挂载时执行一次

  if (loading) return <p>加载中…</p>
  if (error) return <p role="alert">出错了：{error}</p>
  if (vacations.length === 0) return <p>暂时没有可预订的行程。</p>

  return (
    <div>
      {vacations.map((v) => <VacationCard key={v.sku} vacation={v} />)}
    </div>
  )
}
⚠ 三个状态，一个都不能少

加载中、出错了、空数据 —— 初学者最常见的错误就是只写「成功且有数据」的分支。 结果用户在网速慢时看到一片空白，在接口挂掉时也看到一片空白，完全不知道发生了什么。
在真实项目里，用 TanStack Query 或 SWR 可以把这三个状态、缓存、重试、去重都管起来，比手写 useEffect 可靠得多。

用 RPC 调 API

第 15 章导出的 ApiType 在这里派上用场：

import { hc } from 'hono/client'
import type { ApiType } from '../../src/routes/api'

export const api = hc<ApiType>('/api/v1')

import { api } from './api'

useEffect(() => {
  api.vacations
    .$get({ query: { available: 'true' } })
    .then(async (res) => {
      if (!res.ok) throw new Error('加载失败')
      const body = await res.json()
      setVacations(body.data)     // ← body.data 的类型是自动推导出来的
    })
    .catch((err) => setError(err.message))
}, [])

提交数据

function NotifyForm({ sku }: { sku: string }) {
  const [email, setEmail] = useState('')
  const [status, setStatus] = useState<'idle' | 'sending' | 'done' | 'error'>('idle')

  async function handleSubmit(e: React.FormEvent) {
    e.preventDefault()
    setStatus('sending')

    const res = await api.vacations[':sku'].notify.$post({
      param: { sku },
      json: { email },
    })

    setStatus(res.ok ? 'done' : 'error')
  }

  if (status === 'done') return <p>好的，到季节我们会通知你。</p>

  return (
    <form onSubmit={handleSubmit}>
      <label htmlFor="email">邮箱</label>
      <input
        id="email"
        type="email"
        required
        value={email}
        onChange={(e) => setEmail(e.target.value)}
      />
      <button type="submit" disabled={status === 'sending'}>
        {status === 'sending' ? '提交中…' : '通知我'}
      </button>
      {status === 'error' && <p role="alert">提交失败，请重试。</p>}
    </form>
  )
}

⚠ 服务端必须配合前端路由

用户直接在地址栏输入 /vacations/HR199 并回车，请求会发到服务器。 如果服务器上没有这个路径，就会返回 404 —— 前端路由根本没机会运行。
解决办法是「SPA 回退」：所有没匹配到 API 和静态文件的请求，一律返回 index.html。 

// 1. API 路由优先
app.route('/api/v1', apiRoutes)

// 2. 真实存在的静态文件
app.use('/*', serveStatic({ root: './public' }))

// 3. 其余全部回退到 index.html，交给前端路由
app.get('*', serveStatic({ path: './public/index.html' }))

状态管理什么时候需要

情况用什么
状态只在一个组件里用useState 就够了
父子组件之间传props 往下传，回调往上传
很多层组件都要用（当前用户、主题）React Context
来自服务器的数据（列表、详情）TanStack Query / SWR，不是状态管理库
复杂的纯客户端状态（编辑器、画布）Zustand / Jotai / Redux
★ 大部分「状态管理」其实是「服务器数据缓存」

很多项目把 Redux 塞满了从 API 拿回来的数据，然后手写一堆代码去处理加载状态、 缓存失效、重新拉取、并发请求去重。
这些问题 TanStack Query 已经全部解决了。先分清「这个状态的真相在服务器还是在浏览器」， 再选工具。真相在服务器的，用数据获取库；真正属于客户端的（比如「侧边栏展开了吗」），才用状态管理。

更轻的选择

不是每个项目都需要完整的 React。Hono 生态里有两个更轻的方案：

hono/jsx/dom：客户端也用 Hono 的 JSX

import { render, useState } from 'hono/jsx/dom'

function Counter() {
  const [count, setCount] = useState(0)
  return <button onClick={() => setCount(count + 1)}>点了 {count} 次</button>
}

render(<Counter />, document.getElementById('root')!)

API 和 React 高度相似，但体积小一个数量级。适合「页面基本是服务端渲染的， 只有几个地方需要交互」的场景 —— 而这其实是大多数网站的真实情况。

HonoX：全栈元框架

HonoX 是 Hono 官方的全栈框架， 提供基于文件的路由、服务端渲染、以及「孤岛架构」—— 默认整页服务端渲染，只把标记为「岛」的组件送到客户端做水合。 

app/
├── routes/
│   ├── index.tsx           → /
│   ├── about.tsx           → /about
│   └── vacations/
│       └── [sku].tsx       → /vacations/:sku
├── islands/
│   └── NotifyForm.tsx      ← 只有这个组件的 JS 会发到浏览器
└── server.ts
💡 怎么选
  • 内容为主、少量交互（营销站、博客、文档）→ Hono SSR + hono/jsx/dom
  • 想要文件路由和孤岛架构 → HonoX
  • 交互密集的应用（后台、看板、编辑器）→ Hono API + React/Vue SPA
  • 团队已经很熟 React → 直接上 React，别为了轻量增加学习成本

小结

  • SPA 的价值是「状态 → 界面」的声明式模型，不是「页面不刷新」。
  • 后端在 SPA 架构里只做两件事：提供静态文件、提供 JSON API。
  • 开发时用 Vite 代理避开 CORS；生产同域部署同样不需要 CORS。
  • RPC 客户端让前端拿到后端类型，接口改了当场编译报错。
  • 数据请求一定要处理加载中、出错、空数据三种状态。
  • 服务器要配 SPA 回退，否则刷新子路径会 404。
  • 需要服务器主动推送数据（通知、进度、协作）时，见第 23 章。
  • 不是所有项目都需要 React；hono/jsx/dom 和 HonoX 值得考虑。

动手练习

  1. 用 Vite 建一个 React 前端，通过代理调用你的 /api/v1/vacations，把结果渲染成列表。
  2. 把 fetch 换成 RPC 客户端 hc。然后在后端把某个字段改名，确认前端立刻编译报错。
  3. 加上 react-router 和至少两个页面，配好服务端的 SPA 回退，确认直接访问 /vacations 并刷新不会 404。
  4. 故意把后端停掉，看看你的前端界面表现如何。如果只是一片空白，去补上错误状态。
  5. 把「到季通知」表单做出来，包含提交中禁用按钮、成功提示、失败重试。
