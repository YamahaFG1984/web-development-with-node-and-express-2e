第 10 章

中间件

前面几章我们已经用过好几个中间件了。现在把它讲透。 理解了洋葱模型，你就理解了 Hono 应用的运行机制 —— 因为一个 Hono 应用，本质上就是一堆中间件。

本章目标

  • 彻底理解洋葱模型和 await next() 的含义
  • 自己写中间件，包括「在响应返回前修改它」这种操作
  • 掌握路径匹配和执行顺序规则
  • 了解 Hono 内置的全部中间件，知道遇到问题该找哪个

洋葱模型

中间件就是一个函数：(c, next) => ...。 它在处理函数之前和之后都能插一脚。await next() 是分界线。 

app.use(async (c, next) => {
  console.log('① 进入')
  await next()              // ← 把控制权交给下一层
  console.log('② 出来')
})

动手验证一下。写三个中间件，看看输出顺序：

const app = new Hono()

app.use(async (c, next) => {
  console.log('A 进')
  await next()
  console.log('A 出')
})

app.use(async (c, next) => {
  console.log('B 进')
  await next()
  console.log('B 出')
})

app.get('/', (c) => {
  console.log('  处理函数执行')
  return c.text('ok')
})

A 进
B 进
  处理函数执行
B 出
A 出
★ 和 Express 的关键区别

Express 的中间件是单向管道：调完 next() 就基本结束了， 想在响应发出前做点什么，得去 hack res.end。
Hono 的 next() 是 Promise，await 它就能拿回控制权， 在响应真正返回之前再做处理。压缩、缓存、加响应头、记录耗时 —— 全靠这个。

不调用 next() 会怎样

app.use(async (c, next) => {
  if (!isLoggedIn(c)) {
    return c.redirect('/login')   // 直接返回 → 后面的一律不执行
  }
  await next()
})

不调 next() 就等于拦截。这正是认证、限流、维护模式中间件的工作方式： 条件不满足就直接返回响应，请求根本到不了处理函数。

写自己的中间件

最朴素的写法就是一个函数：

app.use(async (c, next) => {
  const start = Date.now()
  await next()
  const ms = Date.now() - start
  c.res.headers.set('X-Response-Time', `${ms}ms`)
})

但推荐用 createMiddleware，它能带上类型信息（告诉 TypeScript 这个中间件往 c 里放了什么）： 

import { createMiddleware } from 'hono/factory'

export const requestId = createMiddleware<{
  Variables: { requestId: string }
}>(async (c, next) => {
  const id = c.req.header('X-Request-Id') ?? crypto.randomUUID()
  c.set('requestId', id)

  await next()

  c.res.headers.set('X-Request-Id', id)
})

app.use(requestId)

app.get('/', (c) => {
  const id = c.get('requestId')   // ← TypeScript 知道这是 string
  console.log(`[${id}] 处理首页`)
  return c.text('ok')
})

带参数的中间件

如果中间件需要配置，就写一个「返回中间件的函数」：

export function requireRole(role: string) {
  return createMiddleware(async (c, next) => {
    const user = c.get('user')
    if (!user) return c.redirect('/login', 303)
    if (user.role !== role) return c.text('没有权限', 403)
    await next()
  })
}

// 使用
app.use('/admin/*', requireRole('admin'))
ⓘ 为什么内置中间件都要「调用一下」

你会注意到写法是 app.use(logger()) 而不是 app.use(logger) —— 多了一对括号。因为 logger 是个工厂函数，调用它才返回真正的中间件。 忘了括号是很常见的错误，症状是中间件完全不生效或者直接报错。

修改响应

在 next() 之后，c.res 就是即将返回的响应，你可以改它：

app.use(async (c, next) => {
  await next()

  // 加响应头
  c.res.headers.set('X-Powered-By', 'Meadowlark')

  // 甚至可以整个换掉
  if (c.res.status === 404) {
    c.res = new Response('自定义的 404', { status: 404 })
  }
})

捕获错误

app.use(async (c, next) => {
  try {
    await next()
  } catch (err) {
    console.error('[中间件捕获]', err)
    // 上报给监控系统
    throw err          // 继续往上抛，交给 app.onError 统一处理响应
  }
})

异常会沿着洋葱往外冒泡，最终被 app.onError() 接住。 中间件里 try/catch 适合做「记录、上报、清理」，而不是「决定返回什么」—— 返回什么应该统一在 onError 里决定。

顺序与路径匹配

app.use() 的第一个参数可以是路径模式：

app.use(logger())                          // 所有请求
app.use('*', logger())                     // 同上，显式写法
app.use('/admin/*', requireRole('admin'))  // 只有 /admin 下面的
app.use('/api/*', cors())                  // 只有 API
app.get('/x', mw1, mw2, handler)           // 只给这一个路由挂两个中间件
⚠ 中间件必须在路由之前注册

Hono 按注册顺序执行。写在 app.get('/x', ...) 之后的 app.use() 对 /x 是无效的。 「我加了 CORS 怎么不生效」，十有八九是这个原因。

一个完整例子

import { Hono } from 'hono'
import { logger } from 'hono/logger'
import { requestId } from 'hono/request-id'
import { secureHeaders } from 'hono/secure-headers'
import { compress } from 'hono/compress'
import { cors } from 'hono/cors'
import { prettyJSON } from 'hono/pretty-json'
import { serveStatic } from '@hono/node-server/serve-static'
import { sessionMiddleware } from './middleware/session'
import { flashMiddleware } from './middleware/flash'
import * as handlers from './handlers'

export const app = new Hono()

// —— 全局：可观测性 ——
app.use(requestId())
app.use(logger())

// —— 全局：安全与性能 ——
app.use(secureHeaders())
app.use(compress())

// —— 只给 API 加 CORS 和格式化 ——
app.use('/api/*', cors({ origin: ['https://meadowlarktravel.com'] }))
app.use('/api/*', prettyJSON())

// —— 静态资源（命中就直接返回） ——
app.use('/*', serveStatic({ root: './public' }))

// —— 会话（只有页面路由需要，API 用令牌） ——
app.use('/', sessionMiddleware(store, secret))
app.use('/vacations/*', sessionMiddleware(store, secret))
app.use(flashMiddleware)

// —— 路由 ——
app.get('/', handlers.home)
app.get('/about', handlers.about)
app.get('/vacations', handlers.listVacations)
app.get('/api/vacations', handlers.api.listVacations)

// —— 兜底 ——
app.notFound(handlers.notFound)
app.onError(handlers.serverError)

常见坑

⚠ 四个高频错误
  1. 忘了 await。写成 next() 而不是 await next()， 「响应阶段」的代码会在响应还没生成时就执行，行为诡异且难查。
  2. 忘了调用工厂函数。app.use(logger) 少了括号。
  3. 中间件写在路由后面。不生效，而且没有任何报错。
  4. 既返回响应又调 next()。要么拦截（return），要么放行（await next()）， 不要都做。
💡 调试技巧

分不清中间件有没有执行、执行顺序对不对时，临时插一个打印中间件： 

app.use(async (c, next) => {
  console.log('>>> 进入', c.req.method, c.req.path)
  await next()
  console.log('<<< 离开', c.res.status)
})

另外 import { showRoutes } from 'hono/dev' 然后 showRoutes(app) 会把所有注册的路由和中间件打印成一张表，第 25 章会用到。

小结

  • 中间件是 (c, next) => ...；await next() 之前是请求阶段，之后是响应阶段。
  • 不调 next() 就是拦截，这是认证和限流的实现方式。
  • createMiddleware 让中间件塞进 c 的东西带上类型。
  • 注册顺序即执行顺序，中间件必须写在路由之前。
  • Hono 内置了二十多个中间件，遇到通用需求先查表，别自己造。
