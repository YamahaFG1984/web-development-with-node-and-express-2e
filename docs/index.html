Hono 全栈开发：从零到上线

这套教程改编自 O'Reilly 的经典教材《Web Development with Node and Express》（第 2 版）。 原书的知识骨架被完整保留 —— 路由、模板、表单、Cookie、中间件、数据库、API、安全、部署 —— 但所有代码都换成了 Hono 和它的生态。第四部分（第 24–30 章）是原书没有的补充：并发一致性、缓存、队列、Webhook、实时通信、可观测性与支付 —— 这几类问题本地永远复现不出来，却是线上事故的主要来源。

为什么是 Hono？

Express 诞生于 2010 年，那时候 JavaScript 只有一个服务端家园：Node.js。 十几年过去，情况变了：Node.js、Deno、Bun、Cloudflare Workers、Vercel Edge、AWS Lambda…… 每个平台都能跑 JavaScript，但它们的“请求对象”长得都不一样。

Hono（日语「炎」，读作 /ˈhoʊnoʊ/）选择了另一条路：不发明自己的 req 和 res， 而是直接使用浏览器里就有的 Fetch API 标准对象 —— Request、Response、Headers、URL、FormData。 一个 Hono 应用本质上就是一个函数：传进一个 Request，返回一个 Response。

这套教程写给谁

  • 会一点 JavaScript，但没写过服务端的人。每一章都从“为什么需要这个东西”讲起，而不是直接甩 API。
  • 用过 Express，想迁移到 Hono 的人。大量章节里有「Express 这样写 / Hono 这样写」的左右对照。
  • 想系统补齐 Web 后端知识的前端工程师。HTTP、Cookie、会话、CSRF、缓存、CDN，这些概念和框架无关，换了框架也带得走。
ⓘ 需要什么前置知识

会用变量、函数、数组、async/await 就够了。TypeScript 不会也没关系 —— 我们会在第 4 章从零解释用到的每一个类型写法。命令行只需要会 cd 和敲命令。

贯穿全书的例子：云雀旅行

和原书一样，我们会一路建设同一个网站：云雀旅行（Meadowlark Travel）， 一家虚构的俄勒冈州旅游公司。从第 3 章的一个「Hello」开始，到第 32 章把它部署上线， 中途它会长出模板、表单、图片上传、购物车、数据库、REST API、React 前端、第三方登录……

怎么用这套教程

  • 按顺序读。后面的章节会用到前面建立的项目。第 1、2 章是背景，急的话可以跳到第 3 章开始动手。
  • 亲手敲代码。每章末尾都有「动手练习」。看懂和写出来之间的差距，比你想象的大。
  • 遇到 对照 卡片时留意左边。左边是 Express 的写法，右边是 Hono 的写法。如果你没用过 Express，忽略左边即可。

💡 一句话总结

如果你只记住一件事：Hono 应用就是一个 (Request) => Response 的函数， 中间件是包在这个函数外面的一层层洋葱皮。 这套教程剩下的 23 章，都是在解释这句话的各种展开。
