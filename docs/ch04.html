第 4 章

整理项目

前两章我们在「玩」。从这一章起要认真了：定好目录结构，把逻辑拆成模块， 配好 TypeScript 和 Git。这些活儿不酷，但它们决定了三个月后你还改不改得动这个项目。

本章目标

  • 规划一个能长期扩展的目录结构
  • 把路由处理函数抽成独立模块（这也是第 5 章能写测试的前提）
  • 看懂本教程用到的 TypeScript 语法，包括 Hono 的泛型参数
  • 配好 Git 与 .gitignore，理解 package.json 里的版本号写法

目录结构

目录结构没有标准答案，但有一条被反复验证的原则：项目根目录只放配置，源码全在 src/ 里。 下面是本教程会用到的结构，后面章节会往里加东西： 

meadowlark/
├── package.json          项目元信息与依赖
├── tsconfig.json         TypeScript 配置
├── .gitignore            不进版本库的文件
├── README.md             这个项目是什么、怎么跑
├── public/               静态资源，原样发给浏览器
│   ├── css/
│   └── img/
└── src/
    ├── server.tsx        入口：组装应用、启动服务
    ├── app.tsx           应用本体：路由注册（可测试）
    ├── config.ts         配置与密钥读取（第 9 章）
    ├── db.ts             数据库访问层（第 13 章）
    ├── handlers/         路由处理函数
    │   └── index.ts
    ├── middleware/       自定义中间件（第 10 章）
    ├── lib/              纯逻辑工具，不依赖 HTTP
    │   └── fortune.ts
    └── views/            JSX 组件
        ├── layout.tsx
        └── pages.tsx
★ 为什么要把 server 和 app 拆开

app.tsx 只导出一个配置好的 Hono 实例，不监听端口。 server.tsx 才调用 serve()。这样做的好处：测试可以直接 import app， 不用真的开一个服务器（第 5 章会看到）。换运行时时也只要换 server.tsx 一个文件。

拆分现在的代码

src/handlers/index.ts：

import type { Context } from 'hono'
import { getFortune } from '../lib/fortune'
import { Home, About, NotFound, ServerError } from '../views/pages'

export const home = (c: Context) => c.html(<Home />)

export const about = (c: Context) => c.html(<About fortune={getFortune()} />)

export const notFound = (c: Context) => c.html(<NotFound />, 404)

export const serverError = (err: Error, c: Context) => {
  console.error(err)
  return c.html(<ServerError />, 500)
}

src/app.tsx：

import { Hono } from 'hono'
import { serveStatic } from '@hono/node-server/serve-static'
import * as handlers from './handlers'

export const app = new Hono()

app.use('/*', serveStatic({ root: './public' }))

app.get('/', handlers.home)
app.get('/about', handlers.about)

app.notFound(handlers.notFound)
app.onError(handlers.serverError)

src/server.tsx：

import { serve } from '@hono/node-server'
import { app } from './app'

const port = Number(process.env.PORT) || 3000
serve({ fetch: app.fetch, port })
console.log(`服务器已启动：http://localhost:${port}`)

现在每个文件只做一件事。handlers 里的函数是纯函数： 给它一个 Context，它返回一个 Response，没有别的副作用。这种函数最好测。

模块：import 与 export

上面的代码用了 ES 模块语法。它是 JavaScript 的官方模块标准，Hono、Vite、所有现代工具都用它。 三种常见写法： 

// ① 具名导出（推荐，一个文件可以导出多个东西）
export function getFortune() { /* ... */ }
export const VERSION = '1.0'
// 使用：
import { getFortune, VERSION } from './lib/fortune'

// ② 默认导出（一个文件只有一个主角，比如 Hono 应用）
export default app
// 使用：
import app from './app'

// ③ 全部导入成一个命名空间
import * as handlers from './handlers'
handlers.home(c)

// ④ 只导入类型（编译后会被完全删掉，运行时零开销）
import type { Context } from 'hono'
ⓘ 你可能见过 require()

const express = require('express') 是 Node.js 早期的 CommonJS 模块系统。 新项目一律用 import，只要在 package.json 里写上 "type": "module"。 老教程和老库里还大量存在 require，看到时知道是同一件事的旧写法就行。

⚠ 封装很重要

src/lib/fortune.ts 里的 fortunes 数组没有 export。 这不是遗漏 —— 外面根本不需要知道签语是怎么存的。只暴露 getFortune()， 将来把签语换成从数据库读，外部代码一行都不用改。少暴露一点，将来就少改一点。

你需要的 TypeScript

本教程全程用 TypeScript。不是为了赶时髦 —— Hono 最大的优势之一就是类型安全， 用 JavaScript 写等于把一半好处扔掉。但你不需要成为 TypeScript 专家，下面这些就够了。

基础类型标注

let name: string = '云雀'
let price: number = 99.95
let inSeason: boolean = true
let tags: string[] = ['帆船', '啤酒']
let note: string | null = null          // 联合类型：要么字符串要么 null
let maybe?: string                       // 可选：可能是 undefined

// 函数：参数类型 + 返回值类型
function format(price: number, currency: string): string {
  return `${currency} ${price.toFixed(2)}`
}

// 描述一个对象的形状
type Vacation = {
  name: string
  price: number
  tags: string[]
  notes?: string          // 可选字段
}

Hono 的两个泛型参数

这是 Hono 特有的、你迟早会遇到的写法。new Hono() 可以接收一个类型参数， 告诉 TypeScript 「这个应用能访问哪些环境变量、中间件往上下文里塞了什么」： 

type Bindings = {
  DATABASE_URL: string        // 环境变量 / 平台绑定
  COOKIE_SECRET: string
}

type Variables = {
  user: { id: string; name: string }   // 中间件塞进来的值
}

const app = new Hono<{ Bindings: Bindings; Variables: Variables }>()

app.get('/me', (c) => {
  const user = c.get('user')    // ← 类型是 { id: string; name: string }
  const url = c.env.DATABASE_URL // ← 类型是 string
  return c.json(user)
})
💡 现在不懂也没关系

Bindings 会在第 12、13 章（环境变量与数据库）真正用上， Variables 会在第 10 章（中间件）和第 19 章（认证）用上。 现在只要看到这个写法不慌就行。

版本控制

哪怕是一个人的周末项目，也用 Git。它给你三样东西：

  • 历史 —— 三个月后你想知道「这行奇怪的代码为什么在这」，git log 能回答。
  • 归属 —— 团队里知道该找谁问。
  • 试错的胆量 —— 开个分支随便改，不行就丢掉，主线毫发无损。
git init
git add -A
git commit -m "初始提交：云雀旅行骨架"

在 git add 之前先写好 .gitignore：

# 依赖：可以由 package.json 重新装出来，不进版本库
node_modules

# 构建产物
dist
.wrangler

# 密钥：绝对不能提交（第 9 章详谈）
.env
.env.*
.dev.vars

# 系统与编辑器杂物
.DS_Store
*.log
⚠ 密钥一旦提交就等于泄露

就算你下一次提交把它删了，它仍然留在 Git 历史里，任何能 clone 仓库的人都能挖出来。 正确做法是：立刻作废那个密钥并换新的，然后再清理历史。 所以第一天就把 .gitignore 写对。

package.json 与版本号

package.json 干两件事：描述你的项目、列出依赖。 

{
  "name": "meadowlark",
  "version": "0.1.0",
  "type": "module",
  "scripts": {
    "dev": "tsx watch src/server.tsx",
    "start": "tsx src/server.tsx",
    "typecheck": "tsc --noEmit"
  },
  "dependencies": {
    "@hono/node-server": "^1.13.0",
    "hono": "^4.6.0"
  },
  "devDependencies": {
    "@types/node": "^22.0.0",
    "tsx": "^4.19.0",
    "typescript": "^5.6.0"
  }
}
字段含义
type: "module"用 ES 模块语法（import）而不是 CommonJS
dependencies线上运行也需要的包
devDependencies只在开发/构建时需要（测试框架、类型定义、编译器）。用 npm i -D 安装
scripts常用命令的快捷方式，npm run dev 执行

读懂 ^4.6.0

npm 用语义化版本（semver）：主版本.次版本.修订号。

package-lock.json 记录的是实际装了哪些精确版本。它必须提交到 Git —— 这样团队成员和 CI 装出来的依赖树和你完全一致。不要手动编辑它。

README

项目根目录一定要有 README.md。它至少回答三个问题： 

# 云雀旅行

俄勒冈州旅游服务网站，基于 Hono 构建。

## 本地运行

    npm install
    cp .env.example .env    # 填入你自己的密钥
    npm run dev             # http://localhost:3000

## 目录说明

- `src/app.tsx`     路由表
- `src/handlers/`   路由处理函数
- `src/lib/`        与 HTTP 无关的纯逻辑
- `src/views/`      JSX 页面组件
- `public/`         静态资源

小结

  • 源码放 src/，根目录只留配置。分层：入口 → 路由 → 处理函数 → 逻辑/数据。
  • 把 app（应用实例）和 server（启动监听）拆开，测试和换运行时都会受益。
  • 只 export 外部真正需要的东西，其余保持私有。
  • TypeScript 里你现在只需要会：类型标注、type 定义对象形状、import type。
  • 第一天就写好 .gitignore，密钥永远不进版本库。

动手练习

  1. 按本章的结构重构你的项目，确认 npm run dev 仍然正常。
  2. 运行 npm run typecheck。如果有报错，逐个修掉 —— 这些都是 TypeScript 帮你提前发现的 bug。
  3. 把 getFortune() 改成不重复返回上一次的签语。想一想：这个状态应该放在模块里，还是每个请求一份？（提示：多个用户会同时访问）
  4. 初始化 Git 仓库并提交。然后 git log --stat 看看你都提交了什么，确认 node_modules 不在里面。
