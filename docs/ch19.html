第 19 章

集成第三方 API

天气、地图、支付、短信、AI —— 现代应用的很大一部分能力来自别人的服务。 这一章讲怎么调用它们，以及更重要的：怎么在它们出问题时不被拖垮。

本章目标

  • 在服务端用 fetch 调外部 API，处理超时和重试
  • 给云雀旅行的天气组件接上真实数据
  • 用缓存把外部调用次数降下来
  • 做地理编码并在页面上显示地图
  • 用降级和熔断保证「第三方挂了，我不挂」

在哪里调：前端还是后端

⚠ API Key 放前端 = 公开你的信用卡

「打包压缩之后看不出来」是错觉 —— 打开浏览器的 Network 面板， Key 就明晃晃写在请求头或 URL 里。有人写过爬虫专门扫 GitHub 和网页找泄露的 Key。 能计费的 Key 一律不进前端。

服务端的 fetch

Hono 的运行时都内置了 fetch，不用装 axios 之类的库。但直接裸用有几个问题： 

// ❌ 三个隐患
const res = await fetch(url)      // ① 对方不响应就永远挂着
const data = await res.json()     // ② 返回 500 时 res.ok 是 false，但这里不会抛错

写一个带超时、重试和错误检查的封装：

export class HttpError extends Error {
  constructor(public status: number, public url: string, message: string) {
    super(message)
  }
}

type Options = RequestInit & {
  timeoutMs?: number
  retries?: number
}

export async function fetchJson<T>(url: string, opts: Options = {}): Promise<T> {
  const { timeoutMs = 5000, retries = 2, ...init } = opts

  for (let attempt = 0; attempt <= retries; attempt++) {
    // AbortSignal.timeout 是标准 API，所有运行时都有
    const signal = AbortSignal.timeout(timeoutMs)

    try {
      const res = await fetch(url, {
        ...init,
        signal,
        headers: {
          'User-Agent': 'MeadowlarkTravel/1.0 (contact@meadowlarktravel.com)',
          Accept: 'application/json',
          ...init.headers,
        },
      })

      // 4xx 是我们的问题，重试没用，直接抛
      if (res.status >= 400 && res.status < 500) {
        throw new HttpError(res.status, url, `客户端错误 ${res.status}`)
      }

      // 5xx 和 429 可以重试
      if (!res.ok) {
        throw new HttpError(res.status, url, `服务端错误 ${res.status}`)
      }

      return (await res.json()) as T
    } catch (err) {
      const isLast = attempt === retries
      const notRetryable = err instanceof HttpError && err.status < 500 && err.status !== 429

      if (isLast || notRetryable) throw err

      // 指数退避 + 随机抖动，避免所有实例同时重试
      const delay = 2 ** attempt * 200 + Math.random() * 200
      await new Promise((r) => setTimeout(r, delay))
    }
  }

  throw new Error('unreachable')
}
★ 为什么要「指数退避 + 抖动」

对方服务过载时，如果所有客户端都在固定 1 秒后重试，就会形成一波又一波的冲击， 让它永远缓不过来 —— 这叫惊群效应。
每次等待时间翻倍（200ms、400ms、800ms）给对方喘息时间； 再加一点随机抖动，把重试时刻打散。

⚠ 不是所有请求都能重试

幂等的操作（GET、PUT、DELETE）重试是安全的。
非幂等的操作（POST 创建订单、发起支付）重试可能导致重复下单。 这类请求要么不重试，要么让对方支持「幂等键」（每次请求带一个唯一 ID，对方据此去重）。 反过来，你自己的接口也该支持幂等键，否则别人重试你时同样会出问题 —— 见第 20 章。

给天气组件接上真数据

第 7 章我们做了一个天气组件，用的是假数据。现在换成美国国家气象局的真实 API （它免费、不需要 Key，正好用来演示）。 

import { fetchJson } from './http'

export type Forecast = {
  name: string
  weather: string
  temp: string
  iconUrl: string
  forecastUrl: string
}

const LOCATIONS = [
  { name: '波特兰', lat: 45.5155, lng: -122.6793 },
  { name: '本德',   lat: 44.0582, lng: -121.3153 },
  { name: '曼扎尼塔', lat: 45.7184, lng: -123.9351 },
]

async function fetchOne(loc: (typeof LOCATIONS)[number]): Promise<Forecast> {
  // 第一步：用经纬度换到预报接口地址
  const points = await fetchJson<{ properties: { forecast: string } }>(
    `https://api.weather.gov/points/${loc.lat.toFixed(4)},${loc.lng.toFixed(4)}`
  )

  // 第二步：取预报
  const data = await fetchJson<{
    properties: {
      periods: {
        shortForecast: string
        temperature: number
        temperatureUnit: string
        icon: string
      }[]
    }
  }>(points.properties.forecast)

  const now = data.properties.periods[0]

  return {
    name: loc.name,
    weather: now.shortForecast,
    temp: `${now.temperature} °${now.temperatureUnit}`,
    iconUrl: now.icon,
    forecastUrl: points.properties.forecast,
  }
}

export async function getForecasts(): Promise<Forecast[]> {
  // 并发请求，而不是一个接一个
  const results = await Promise.allSettled(LOCATIONS.map(fetchOne))

  // 部分失败不影响其他，只是少显示一个城市
  return results
    .filter((r): r is PromiseFulfilledResult<Forecast> => r.status === 'fulfilled')
    .map((r) => r.value)
}
★ Promise.allSettled 还是 Promise.all

Promise.all：任何一个失败，整个都失败。适合「缺一不可」的场景。
Promise.allSettled：等所有的都结束，分别报告成败。
天气组件里，一个城市取不到不该让整个组件消失 —— 所以用 allSettled。

缓存：最重要的一步

上面的代码每次页面渲染都会打 6 次外部请求。一千个用户访问首页就是 6000 次 —— 又慢、又可能被对方限流、还可能产生费用。天气数据 15 分钟更新一次就够了。 

type Entry<T> = { value: T; expiresAt: number }

/**
 * 把一个异步函数包装成带缓存的版本。
 * 关键特性：缓存过期后如果刷新失败，会继续返回旧数据（stale-while-error）
 */
export function withCache<T>(
  fn: () => Promise<T>,
  ttlMs: number
): () => Promise<T> {
  let entry: Entry<T> | null = null
  let inflight: Promise<T> | null = null

  return async () => {
    const now = Date.now()

    // 缓存有效，直接返回
    if (entry && entry.expiresAt > now) return entry.value

    // 已经有一个请求在路上了，跟着它就行（避免并发时打出多个请求）
    if (inflight) return inflight

    inflight = fn()
      .then((value) => {
        entry = { value, expiresAt: Date.now() + ttlMs }
        return value
      })
      .catch((err) => {
        // 刷新失败：有旧数据就先用旧的，总比页面报错强
        if (entry) {
          console.warn('刷新失败，继续使用过期数据', err)
          return entry.value
        }
        throw err
      })
      .finally(() => { inflight = null })

    return inflight
  }
}

export const getCachedForecasts = withCache(getForecasts, 15 * 60 * 1000)

// 边缘环境的版本：用 KV 做共享缓存
export async function getForecastsFromKV(kv: KVNamespace): Promise<Forecast[]> {
  const cached = await kv.get<Forecast[]>('weather:forecasts', 'json')
  if (cached) return cached

  const fresh = await getForecasts()
  await kv.put('weather:forecasts', JSON.stringify(fresh), { expirationTtl: 900 })
  return fresh
}

// 在中间件里注入，让所有页面都能用（第 7 章的 partial 现在有真数据了）
app.use('*', async (c, next) => {
  c.set('forecasts', await getForecastsFromKV(c.env.CACHE))
  await next()
})

地理编码与地图

地理编码就是把「俄勒冈州胡德河市」这样的地址转成经纬度。 这类接口通常按调用次数收费，所以更要缓存 —— 而且是永久缓存： 一个地址的坐标基本不会变。 

export async function geocode(address: string, apiKey: string) {
  const url = new URL('https://maps.googleapis.com/maps/api/geocode/json')
  url.searchParams.set('address', address)
  url.searchParams.set('key', apiKey)

  const data = await fetchJson<{
    status: string
    results: { geometry: { location: { lat: number; lng: number } } }[]
  }>(url.toString())

  if (data.status !== 'OK' || data.results.length === 0) return null

  return data.results[0].geometry.location
}

// 一次性脚本：把坐标写进数据库，之后再也不用调这个 API
const rows = await db.select().from(vacations).where(isNull(vacations.lat))

for (const v of rows) {
  const loc = await geocode(v.locationSearch, process.env.GOOGLE_API_KEY!)
  if (!loc) {
    console.warn(`地理编码失败：${v.sku} · ${v.locationSearch}`)
    continue
  }

  await db.update(vacations)
    .set({ lat: loc.lat, lng: loc.lng })
    .where(eq(vacations.sku, v.sku))

  console.log(`${v.name} → ${loc.lat}, ${loc.lng}`)
  await new Promise((r) => setTimeout(r, 200))   // 尊重对方的速率限制
}
★ 分清「一次性」和「每次请求」

地理编码属于数据准备，应该在录入数据时做一次，把结果存进数据库。
绝对不要在渲染页面时实时调用 —— 那是把一个 O(1) 的操作变成了 O(访问量)。 用户请求路径上的每一次外部调用，都是一个潜在的故障点和账单项。

显示地图

地图 SDK 是少数应该在前端调用的场景（它本来就是画在浏览器里的）。 但仍然要保护好 Key： 

export const VacationsMap: FC<{ vacations: Vacation[]; mapKey: string }> = ({
  vacations, mapKey,
}) => (
  <>
    <div id="map" style="height:480px"></div>
    {/* 用 JSON 传数据给前端脚本，避免拼接字符串造成注入 */}
    <script
      type="application/json"
      id="map-data"
      dangerouslySetInnerHTML={{
        __html: JSON.stringify(
          vacations
            .filter((v) => v.lat && v.lng)
            .map((v) => ({ name: v.name, lat: v.lat, lng: v.lng, url: `/vacations/${v.slug}` }))
        ),
      }}
    />
    <script src={`https://maps.googleapis.com/maps/api/js?key=${mapKey}&callback=initMap`} async></script>
    <script src="/js/map.js" defer></script>
  </>
)
💡 前端 Key 要加限制

地图这类必须暴露在前端的 Key，一定要在服务商控制台设置域名白名单 （只允许 meadowlarktravel.com 使用）和用量上限。 这样别人抄走了也用不了，而且万一被滥用，损失有上限。

别人挂了，我不能挂

第三方服务一定会出问题 —— 超时、限流、返回格式变了、干脆下线。 你的应用要能撑住。三个层次：

① 降级

app.get('/', async (c) => {
  let forecasts: Forecast[] = []
  try {
    forecasts = await getCachedForecasts()
  } catch (err) {
    console.error('天气数据不可用', err)
    // 不抛出去。首页的主要内容和天气无关
  }

  return c.html(<HomePage forecasts={forecasts} />)
})

// 视图要能处理「没有数据」
export const WeatherWidget: FC<{ forecasts: Forecast[] }> = ({ forecasts }) => {
  if (forecasts.length === 0) return null   // 干脆不显示，好过显示一个报错框
  return <div class="weather">{/* ... */}</div>
}

② 熔断

如果对方已经连续失败了十次，第十一次大概率还是失败。 继续调用只会浪费时间、拖慢你自己的响应。熔断器会在失败到一定次数后 「跳闸」，一段时间内直接失败，不再发出请求。 

export function createBreaker<T>(fn: () => Promise<T>, opts = { threshold: 5, resetMs: 60_000 }) {
  let failures = 0
  let openUntil = 0

  return async (): Promise<T> => {
    if (Date.now() < openUntil) {
      throw new Error('熔断器已跳闸，暂时不调用该服务')
    }

    try {
      const result = await fn()
      failures = 0                       // 成功一次就重置
      return result
    } catch (err) {
      failures++
      if (failures >= opts.threshold) {
        openUntil = Date.now() + opts.resetMs
        console.error(`熔断器跳闸，${opts.resetMs / 1000} 秒后重试`)
      }
      throw err
    }
  }
}

③ 超时预算

⚠ 你的超时必须比调用方的超时短

如果浏览器等你 10 秒，而你等第三方 30 秒，那么第三方一慢， 用户看到的就是浏览器超时 —— 而你的服务器还在傻等，占着连接和内存。
给每个外部调用设置明确的超时，并且加起来要小于你自己的响应目标。 比如：目标 2 秒响应，那么两个外部调用各给 800 ms。

社交媒体嵌入

⚠ 一个分享按钮可能拖慢整个页面

第三方的嵌入脚本（分享按钮、评论组件、客服挂件、统计代码）通常会： 加载几百 KB 的 JS、发起十几个额外请求、插入 iframe、拖慢首屏、 并且它们的可用性完全不受你控制。

更好的做法：

  • 分享按钮用纯链接实现（https://twitter.com/intent/tweet?url=...），零 JavaScript。
  • 确实需要的嵌入，用惰性加载：先显示一个占位图，用户点击后才真正加载。
  • 所有第三方脚本加 defer 或 async，绝不阻塞渲染。
  • 用第 18 章的 CSP 限制第三方脚本能做什么。

小结

  • 默认在后端调第三方 API：保护 Key、能缓存、无 CORS、可统一处理错误。
  • fetch 要包一层：超时、区分可重试与不可重试、指数退避加抖动。
  • 缓存是最重要的优化，边缘环境要用共享缓存。
  • 地理编码这类「结果不变」的调用，在数据录入时做一次并存库。
  • 用降级、熔断、超时预算保证第三方故障不会传染给你。
  • 第三方前端脚本要惰性加载，能用纯链接就别用脚本。

动手练习

  1. 实现 fetchJson，用它调用任意一个公开 API。把超时改成 1 毫秒，确认它正确抛出超时错误而不是永久挂起。
  2. 给天气组件接上真实数据并加上 15 分钟缓存。在日志里打印实际发出的外部请求，刷新页面十次，确认只发了一轮。
  3. 把天气 API 的地址故意改错，确认首页仍然正常显示，只是没有天气组件。
  4. 实现熔断器，用一个必定失败的 URL 测试：连续失败 5 次后，第 6 次应该立刻失败而不发请求。
  5. 检查你的项目：用户请求路径上有几个外部调用？每一个的超时是多少？加起来会不会超过你的响应目标？
