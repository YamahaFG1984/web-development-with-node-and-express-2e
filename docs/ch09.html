第 9 章

Cookie 与会话

HTTP 是无状态的：服务器处理完一个请求就把你忘干净了。 可我们需要「记住用户已登录」「记住购物车里有什么」。这一章讲这个记忆是怎么造出来的。

本章目标

  • 理解无状态协议为什么需要 Cookie
  • 用 Hono 的 cookie 辅助函数读写、删除 Cookie
  • 搞懂 httpOnly、secure、sameSite 这几个关键选项
  • 用签名 Cookie 防篡改，并把密钥安全地放在代码之外
  • 实现服务端会话与 Flash 消息

无状态是什么意思

机制非常朴素：服务器在响应头里写 Set-Cookie: 名字=值， 浏览器存下来，之后对同一个站点的每个请求都在 Cookie 请求头里带回去。 没有魔法。

关于 Cookie 你必须知道的五件事

👁

用户能看见

打开开发者工具就能看到所有 Cookie 的内容。不要往里面放秘密。

✏

用户能改

可以随手把 role=user 改成 role=admin。不要信任未签名的 Cookie。

🗑

用户能删

可以清空或禁用 Cookie。你的应用要在没有 Cookie 时也能给出合理的行为。

📋

每次请求都带

包括图片和 CSS 的请求。Cookie 越大，每个请求就越慢。控制在几百字节以内。

⚖

受法规约束

非必要 Cookie（分析、广告）在很多地区需要用户同意。功能性 Cookie 通常豁免。

在 Hono 里操作 Cookie

import { getCookie, setCookie, deleteCookie } from 'hono/cookie'

app.get('/cookie-demo', (c) => {
  // 读
  const theme = getCookie(c, 'theme')          // string | undefined
  const all = getCookie(c)                     // 所有 cookie 组成的对象

  // 写
  setCookie(c, 'theme', 'dark', {
    path: '/',
    httpOnly: true,
    secure: true,
    sameSite: 'Lax',
    maxAge: 60 * 60 * 24 * 30,                 // 30 天，单位是秒
  })

  // 删
  deleteCookie(c, 'old-cookie', { path: '/' })

  return c.text(`当前主题：${theme ?? '未设置'}`)
})

选项详解

选项作用建议
httpOnly 设为 true 后，浏览器里的 JavaScript 读不到这个 Cookie 会话类 Cookie 一律开启。这样即使页面被注入了恶意脚本，也偷不走会话 ID
secure 只在 HTTPS 连接上发送 生产环境一律开启。本地 http://localhost 开发时要关掉
sameSite 控制跨站请求要不要带上这个 Cookie 'Lax' 是好默认值，能挡掉大部分 CSRF 攻击（第 19 章详述）
maxAge 存活秒数。不设的话关闭浏览器就消失（叫会话 Cookie） 按需要设。「记住我」通常是 30 天
path 只在哪些路径下发送。有隐含的通配符：/foo 也匹配 /foo/bar 通常写 '/'
domain 可以让子域名共享。不能设成别人的域名 不需要跨子域就别设

把密钥放到代码之外

下面要用到签名密钥。在写之前，先把「密钥怎么管」这件事做对，因为它一旦做错就很难补救。

规则：密钥永远不写进源代码，永远不提交到 Git。用环境变量。

# 本地开发用，这个文件在 .gitignore 里
COOKIE_SECRET=dGhpcy1pcy1hLXJhbmRvbS1zZWNyZXQtc3RyaW5n
DATABASE_URL=postgres://localhost:5432/meadowlark

# 这个文件要提交，告诉队友需要哪些变量（但不含真实值）
COOKIE_SECRET=
DATABASE_URL=

生成一个随机密钥：

node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"

写一个统一的读取入口，顺便做启动时校验：

import { z } from 'zod'

const schema = z.object({
  COOKIE_SECRET: z.string().min(32, 'COOKIE_SECRET 至少 32 个字符'),
  DATABASE_URL: z.string().url(),
  NODE_ENV: z.enum(['development', 'test', 'production']).default('development'),
})

const parsed = schema.safeParse(process.env)

if (!parsed.success) {
  console.error('环境变量配置有误：')
  console.error(parsed.error.flatten().fieldErrors)
  process.exit(1)     // 宁可启动不了，也不要带着错配置跑起来
}

export const config = parsed.data
export const isProduction = config.NODE_ENV === 'production'
★ 快速失败胜过慢慢出错

没有这段校验的话，忘了配 COOKIE_SECRET 的后果是：应用正常启动， 用 undefined 当密钥去签名，一切看起来都好，直到某天有人发现签名可以伪造。 启动时崩溃是件好事 —— 它把一个隐蔽的安全漏洞变成了一条明显的报错。

ⓘ 不同运行时读环境变量的方式

Node 用 process.env，Cloudflare Workers 用 c.env，Deno 用 Deno.env。 Hono 提供了统一入口：import { env } from 'hono/adapter'，然后 const { KEY } = env(c)。 需要跨运行时的代码用它。第 12 章会详细讲。

签名 Cookie

签名不是加密 —— 内容依然是可读的。它做的是防篡改： 服务器在 Cookie 值后面附一个用密钥算出的校验码，读的时候重新算一遍对比。 用户改了值但算不出正确的校验码，服务器就知道这是伪造的。 

import { getSignedCookie, setSignedCookie } from 'hono/cookie'
import { config } from './config'

app.get('/set', async (c) => {
  await setSignedCookie(c, 'user_id', 'u_12345', config.COOKIE_SECRET, {
    path: '/',
    httpOnly: true,
    secure: isProduction,
    sameSite: 'Lax',
    maxAge: 60 * 60 * 24 * 7,
  })
  return c.text('已设置')
})

app.get('/read', async (c) => {
  const userId = await getSignedCookie(c, config.COOKIE_SECRET, 'user_id')

  // 三种可能的返回值，一定要分清
  if (userId === undefined) return c.text('没有这个 cookie')
  if (userId === false)     return c.text('cookie 被篡改过！', 400)

  return c.text(`用户 ID：${userId}`)
})
⚠ false 和 undefined 是两回事

undefined 表示「没这个 Cookie」，很正常。 false 表示「有这个 Cookie 但签名对不上」—— 这几乎一定是有人在动手脚， 应该记日志、清掉这个 Cookie，必要时告警。 用 if (!userId) 会把两种情况混为一谈，看不出攻击。

会话

Cookie 只能存一小段文本。要记住「购物车里有三件商品，用户偏好人民币，上次浏览到第二页」 这种复杂状态，就需要会话（session）。

两种做法：

⚠ 不要用「内存里的对象」存会话

很多教程会写 const sessions = new Map()。开发时能用，上线必炸： 重启进程会话全没，跑两个实例的话用户一半请求是登录状态一半不是。 会话存储必须是进程外的、多实例共享的。

写一个会话中间件

Hono 核心没有内置会话（因为存储方式差别太大）。我们自己写一个，这也正好是理解中间件的好练习。 先定义存储接口，实现可以随时替换： 

export type SessionData = Record<string, unknown>

export interface SessionStore {
  get(id: string): Promise<SessionData | null>
  set(id: string, data: SessionData, ttlSeconds: number): Promise<void>
  destroy(id: string): Promise<void>
}

/** 开发用：进程内存。上线务必换掉 */
export class MemoryStore implements SessionStore {
  #map = new Map<string, { data: SessionData; expiresAt: number }>()

  async get(id: string) {
    const entry = this.#map.get(id)
    if (!entry) return null
    if (entry.expiresAt < Date.now()) {
      this.#map.delete(id)
      return null
    }
    return entry.data
  }

  async set(id: string, data: SessionData, ttl: number) {
    this.#map.set(id, { data, expiresAt: Date.now() + ttl * 1000 })
  }

  async destroy(id: string) {
    this.#map.delete(id)
  }
}

然后是中间件本身：

import { createMiddleware } from 'hono/factory'
import { getSignedCookie, setSignedCookie } from 'hono/cookie'
import type { SessionStore, SessionData } from '../lib/session-store'

const COOKIE_NAME = 'sid'
const TTL = 60 * 60 * 24 * 7      // 7 天

export type SessionVariables = {
  session: SessionData
  destroySession: () => Promise<void>
}

export function sessionMiddleware(store: SessionStore, secret: string) {
  return createMiddleware<{ Variables: SessionVariables }>(async (c, next) => {
    // 1. 从 cookie 里拿会话 ID
    const raw = await getSignedCookie(c, secret, COOKIE_NAME)
    let id = typeof raw === 'string' ? raw : undefined

    // 2. 载入会话数据（没有就是空对象）
    let data: SessionData = (id && (await store.get(id))) || {}

    c.set('session', data)
    c.set('destroySession', async () => {
      if (id) await store.destroy(id)
      id = undefined
      data = {}
      c.set('session', data)
    })

    // 3. 交给后面的处理函数
    await next()

    // 4. 请求处理完之后，把（可能被改过的）数据写回去
    const current = c.get('session')
    if (Object.keys(current).length > 0) {
      if (!id) {
        id = crypto.randomUUID()
        await setSignedCookie(c, COOKIE_NAME, id, secret, {
          path: '/',
          httpOnly: true,
          secure: process.env.NODE_ENV === 'production',
          sameSite: 'Lax',
          maxAge: TTL,
        })
      }
      await store.set(id, current, TTL)
    }
  })
}

接上去：

import { sessionMiddleware } from './middleware/session'
import { MemoryStore } from './lib/session-store'
import { config } from './config'

const app = new Hono<{ Variables: SessionVariables }>()

app.use('*', sessionMiddleware(new MemoryStore(), config.COOKIE_SECRET))

app.get('/set-currency/:currency', (c) => {
  const session = c.get('session')
  session.currency = c.req.param('currency')
  return c.redirect('/vacations', 303)
})

app.get('/vacations', async (c) => {
  const currency = (c.get('session').currency as string) ?? 'CNY'
  // ...按 currency 换算价格
})
ⓘ 注意 await next() 前后的分工

next() 之前：准备工作（读 Cookie、载入数据）。
next() 之后：收尾工作（保存数据、设置 Cookie）。
这就是「洋葱模型」，第 10 章会把它讲透。

Flash 消息

Flash 消息是「显示一次就消失」的提示，比如提交表单后跳转到新页面时的那句「保存成功」。 它需要跨越一次重定向，正好用会话实现： 

import { createMiddleware } from 'hono/factory'

export type Flash = {
  type: 'success' | 'danger' | 'info'
  intro: string
  message: string
}

export const flashMiddleware = createMiddleware(async (c, next) => {
  const session = c.get('session')

  // 把会话里的 flash 取出来，放到本次请求的变量里
  c.set('flash', session.flash as Flash | undefined)
  // 然后立刻从会话里删掉 —— 它只显示这一次
  delete session.flash

  await next()
})

// 设置：在重定向之前写入会话
app.post('/newsletter/signup', zValidator('form', schema, (result, c) => {
  if (!result.success) {
    c.get('session').flash = {
      type: 'danger',
      intro: '填写有误',
      message: '请检查你输入的邮箱地址。',
    }
    return c.redirect('/newsletter', 303)
  }
}), async (c) => {
  await db.addSubscriber(c.req.valid('form'))
  c.get('session').flash = {
    type: 'success',
    intro: '订阅成功！',
    message: '我们会把最新行程发到你的邮箱。',
  }
  return c.redirect('/newsletter/archive', 303)
})

// 显示：在布局里统一渲染
export const Layout: FC<{ flash?: Flash }> = ({ flash, children }) => (
  <body>
    {flash && (
      <div class={`alert alert-${flash.type}`} role="alert">
        <strong>{flash.intro}</strong> {flash.message}
      </div>
    )}
    <main>{children}</main>
  </body>
)

会话适合装什么

适合放在会话里不适合
登录用户的 ID 用户的完整资料（会过期，直接查库）
购物车（下单前） 订单（必须落库）
界面偏好：货币、语言、排序方式 权限判断的结果（可能已变，每次重新判断）
Flash 消息 大块数据、缓存（用专门的缓存层）
多步表单的中间状态 任何丢了就出大事的东西
💡 API 通常不用会话

会话依赖 Cookie，Cookie 依赖浏览器。手机 App、第三方服务调你的 API 时没有 Cookie。 那种场景用 JWT 或 API Key（第 19 章）。 简单判断：给浏览器用的用会话，给程序用的用令牌。

小结

  • Cookie 是浏览器替服务器保管的小纸条，用户可读、可改、可删。
  • 会话 Cookie 必须 httpOnly；生产环境必须 secure；sameSite: 'Lax' 是好默认。
  • 签名 Cookie 防篡改不防偷看；密钥必须放在环境变量里，启动时校验。
  • 会话优先选「Cookie 存 ID + 服务端存数据」，存储必须是进程外共享的。
  • Flash 消息 = 写会话 + 重定向 + 读后即删。

动手练习

  1. 做一个货币切换功能：/set-currency/:cur 存到会话，行程页按会话里的货币显示价格。重启服务器后确认偏好丢失（因为用的是 MemoryStore）—— 这正是第 13 章要解决的问题。
  2. 在浏览器开发者工具里找到你的 sid Cookie，手动改掉一个字符，刷新页面。确认服务器识别出了篡改（getSignedCookie 返回 false）。
  3. 把 httpOnly 临时关掉，在控制台执行 document.cookie，看看能读到什么。然后打开它再试一次，体会这个选项的价值。
  4. 给会话中间件加上「登出」路由 /logout，调用 destroySession() 并清掉 Cookie。
