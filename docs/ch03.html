第 3 章

用 Hono 节省时间

把第 2 章那个手写服务器用 Hono 重写一遍。同样的功能，代码会短一半， 而且加新页面时不用再动老代码。云雀旅行网站从这一章开始正式动工。

本章目标

  • 用 npm create hono 或手工方式建立项目
  • 写出第一批路由，并配好 404 与错误处理
  • 用 JSX 写页面和布局，理解「视图」和「静态资源」的区别
  • 用 serveStatic 一行搞定静态文件
  • 在页面里塞进动态内容

脚手架

Hono 提供了一个交互式脚手架，一条命令就能生成配好的项目： 

npm create hono@latest meadowlark

它会问你目标运行时（选 nodejs）和包管理器，然后生成一个能直接跑的骨架。 这是真实项目里最省事的做法。

ⓘ 但本章我们手工搭

脚手架会替你做很多决定，而你现在需要知道每个文件为什么在那里。 等你读完第 4 章，再回头用脚手架，你会明白它生成的每一行。

接着第 2 章的目录继续，装上 Hono：

npm install hono

第一个 Hono 应用

把 src/server.ts 整个换成：

import { serve } from '@hono/node-server'
import { Hono } from 'hono'

const app = new Hono()

// 404：没有任何路由匹配上时调用
app.notFound((c) => c.text('404 - 页面不存在', 404))

// 500：任何路由里抛出异常时调用
app.onError((err, c) => {
  console.error(err)
  return c.text('500 - 服务器错误', 500)
})

const port = Number(process.env.PORT) || 3000
serve({ fetch: app.fetch, port })
console.log(`服务器已启动：http://localhost:${port}`)

跑起来（npx tsx src/server.ts）访问首页，你会看到「404 - 页面不存在」。 这是对的 —— 我们一个路由都还没注册。

★ 记住 app.fetch

app.fetch 就是我们在第 2 章手写的那个 (request) => Response 函数。 Hono 应用的本质，就是把你注册的所有路由和中间件编译成这一个函数。 所以它能被塞进任何接受标准 fetch 处理器的平台。

加上路由

在 app.notFound 之前加两个路由：

app.get('/', (c) => c.text('云雀旅行'))

app.get('/about', (c) => c.text('关于云雀旅行'))

app.get(path, handler) 注册一个只响应 GET 请求的路由。 同理还有 app.post、app.put、app.delete、app.patch， 以及匹配所有方法的 app.all。

第 2 章：手写
const url = new URL(request.url)
const path = url.pathname
  .replace(/\/+$/, '')
  .toLowerCase()

switch (path) {

      headers: {
        'Content-Type':
          'text/plain; charset=utf-8'
      }
    })
  // ...
}
第 3 章：Hono
app.get('/', (c) => c.text('云雀旅行'))
URL 解析、方法匹配、字符集、Content-Type —— 全都替你处理了。

顺序很重要

Hono 按注册顺序匹配路由。app.notFound() 是个例外（它总是最后兜底）， 但普通路由和中间件严格按你写的顺序执行。这一点在第 10 章会详细讲，现在只要记住一条规则： 具体的路由写在前面，笼统的写在后面。 

// ❌ 错误：/about/contact 永远走不到
app.get('/about/*', (c) => c.text('关于'))
app.get('/about/contact', (c) => c.text('联系我们'))

// ✅ 正确
app.get('/about/contact', (c) => c.text('联系我们'))
app.get('/about/*', (c) => c.text('关于'))

视图与布局

纯文本网站没人看。我们需要返回 HTML —— 但不是把 HTML 字符串拼在 JavaScript 里（那样很快会失控）。 我们需要视图（view）：一个能塞进动态数据的 HTML 模板。

Hono 内置了 JSX 支持。如果你写过 React，语法完全一样；如果没写过，把它理解成 「可以在 JavaScript 里直接写 HTML 标签，并且用 {} 插值」就行。

配置 TypeScript

在项目根目录建 tsconfig.json：

{
  "compilerOptions": {
    "target": "ESNext",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "strict": true,
    "skipLibCheck": true,
    "types": ["node"],
    "jsx": "react-jsx",
    "jsxImportSource": "hono/jsx"
  }
}

关键是最后两行：告诉 TypeScript「遇到 JSX 语法时，用 hono/jsx 而不是 React 来编译」。 还要在 package.json 里加 "type": "module"，我们用的是 ES 模块语法。

布局

网站每个页面的 <head>、页头、页脚都差不多。把这些公共部分抽出来，就是布局（layout）。 新建 src/views/layout.tsx： 

import type { FC, PropsWithChildren } from 'hono/jsx'

export const Layout: FC<PropsWithChildren<{ title?: string }>> = (props) => (
  <html lang="zh-CN">
    <head>
      <meta charset="utf-8" />
      <meta name="viewport" content="width=device-width,initial-scale=1" />
      <title>{props.title ?? '云雀旅行'}</title>
      <link rel="stylesheet" href="/css/main.css" />
    </head>
    <body>
      <header>
        <img src="/img/logo.png" alt="云雀旅行" width="120" />
      </header>
      <main>{props.children}</main>
      <footer>&copy; 2026 云雀旅行</footer>
    </body>
  </html>
)
ⓘ JSX 的三个语法要点
  • class 要写成 class（Hono 的 JSX 里两种都支持，但推荐 class）。
  • 标签必须闭合：<br />、<img ... />。
  • {props.children} 是「把外面包着的内容放这里」的占位符。

页面

新建 src/views/pages.tsx：

import type { FC } from 'hono/jsx'
import { Layout } from './layout'

export const Home: FC = () => (
  <Layout title="云雀旅行 · 首页">
    <h1>欢迎来到云雀旅行</h1>
    <p>有疑问？看看我们的 <a href="/about">关于页面</a>。</p>
  </Layout>
)

export const About: FC<{ fortune: string }> = ({ fortune }) => (
  <Layout title="关于云雀旅行">
    <h1>关于云雀旅行</h1>
    {fortune && (
      <>
        <p>今日签语：</p>
        <blockquote>{fortune}</blockquote>
      </>
    )}
  </Layout>
)

export const NotFound: FC = () => (
  <Layout title="404"><h1>404 - 页面不存在</h1></Layout>
)

export const ServerError: FC = () => (
  <Layout title="500"><h1>500 - 服务器错误</h1></Layout>
)

渲染

把路由改成返回 JSX：

import { Home, About, NotFound, ServerError } from './views/pages'

app.get('/', (c) => c.html(<Home />))

app.get('/about', (c) => c.html(<About fortune="山高路远，坑深。" />))

app.notFound((c) => c.html(<NotFound />, 404))

app.onError((err, c) => {
  console.error(err)
  return c.html(<ServerError />, 500)
})
⚠ 文件后缀要改

含有 JSX 语法的文件后缀必须是 .tsx（或 .jsx），不能是 .ts。 把 src/server.ts 改名为 src/server.tsx，运行命令也相应改成 npx tsx src/server.tsx。

静态文件

第 2 章我们为每个文件写了一个 case。Hono 用一行中间件解决： 

import { serveStatic } from '@hono/node-server/serve-static'

// 放在所有路由之前
app.use('/*', serveStatic({ root: './public' }))

现在 public/img/logo.png 可以通过 /img/logo.png 访问， public/css/main.css 通过 /css/main.css 访问。MIME 类型自动判断， 路径穿越自动拦截。注意 URL 里没有 public —— 这个目录名对客户端是不可见的。

⚠ 静态中间件会抢路由

如果你在 public/ 里放一个 index.html，访问 / 时返回的会是它， 而不是你的 app.get('/') 路由 —— 因为静态中间件先执行。遇到「我明明写了路由却不生效」， 先看看 public/ 里有没有同名文件。

视图里的动态内容

上面的签语是写死的。让它每次刷新都变 —— 这才叫「动态内容」。 先建个模块 src/lib/fortune.ts： 

const fortunes = [
  '征服你的恐惧，否则它们会征服你。',
  '河流需要源头。',
  '不要害怕你不了解的事物。',
  '你将迎来一个愉快的惊喜。',
  '只要可能，就把事情做简单。',
]

export function getFortune(): string {
  return fortunes[Math.floor(Math.random() * fortunes.length)]
}

然后在路由里用它：

import { getFortune } from './lib/fortune'

app.get('/about', (c) => c.html(<About fortune={getFortune()} />))

刷新几次 /about，签语会变。

★ 静态 vs 动态，界限在哪

/img/logo.png 是静态资源：每次请求返回的字节完全一样，可以放 CDN，可以长期缓存。
/about 是视图：每次请求都要执行代码才能算出结果。哪怕结果碰巧一样，它也不能被无脑缓存。
这个区分会在第 18 章（静态资源与 CDN）变得非常重要。

完整代码

import { serve } from '@hono/node-server'
import { serveStatic } from '@hono/node-server/serve-static'
import { Hono } from 'hono'
import { getFortune } from './lib/fortune'
import { Home, About, NotFound, ServerError } from './views/pages'

const app = new Hono()

app.use('/*', serveStatic({ root: './public' }))

app.get('/', (c) => c.html(<Home />))
app.get('/about', (c) => c.html(<About fortune={getFortune()} />))

app.notFound((c) => c.html(<NotFound />, 404))
app.onError((err, c) => {
  console.error(err)
  return c.html(<ServerError />, 500)
})

const port = Number(process.env.PORT) || 3000
serve({ fetch: app.fetch, port })
console.log(`服务器已启动：http://localhost:${port}`)

为了不用每次手动重启，在 package.json 里加个脚本：

{
  "type": "module",
  "scripts": {
    "dev": "tsx watch src/server.tsx",
    "start": "tsx src/server.tsx"
  }
}

以后开发就 npm run dev，改文件自动重启。

小结

  • app.get(path, handler) 注册路由；处理函数拿到 c，返回响应。
  • app.notFound() 和 app.onError() 兜底 404 和异常。
  • 路由按注册顺序匹配，具体的写前面。
  • JSX 组件 + c.html() = 服务端渲染的页面；布局组件消除重复的 HTML 骨架。
  • serveStatic() 一行搞定静态文件，但它会抢在路由之前匹配。
